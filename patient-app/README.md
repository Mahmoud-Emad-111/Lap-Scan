# Lap Patient App

بوابة مريض مستقلة مبنية بـ React وTypeScript وVite، بواجهة عربية RTL ومناسبة للموبايل وتجهيز لاحق للـCapacitor. التطبيق بيتصل بباك إند Laravel الحالي؛ مش بيخزن نتائج أو بيانات طبية في `localStorage`.

## المتطلبات والتشغيل

- Node.js 20.19+ أو 22.12+
- PHP/Composer لتشغيل Laravel API

من جذر المشروع:

```powershell
Copy-Item patient-app\.env.example patient-app\.env
npm --prefix patient-app install
npm --prefix patient-app run dev
```

شغّل Laravel في نافذة تانية:

```powershell
php artisan serve --host=127.0.0.1 --port=8000
```

يمكن تشغيل التطبيق من Docker Compose كخدمة مستقلة باسم `app`:

```powershell
docker compose up -d --build app
```

عنوان التطبيق الافتراضي `http://localhost:5174`، والـAPI بيستخدم Laravel/Nginx الحالي على `http://localhost`. لوحة المختبر تفضل على `http://localhost:5173`. لو المنفذ 5174 مش متاح، غيّره باستخدام `PATIENT_APP_PORT`.

لتشغيل فحوصات التطبيق:

```powershell
npm --prefix patient-app run types:check
npm --prefix patient-app run build
```

المخرجات بتكون في `patient-app/dist`.

## الإعدادات

| المتغير | الاستخدام | مثال محلي |
| --- | --- | --- |
| `VITE_API_BASE_URL` | أصل Laravel API من غير `/api` | `http://localhost:8000` |
| `VITE_REVERB_APP_KEY` | المفتاح العام لتطبيق Reverb؛ يجب أن يطابق إعداد Laravel | `local-reverb-key` محليًا |
| `VITE_REVERB_HOST` | اسم مضيف WebSocket | `127.0.0.1` |
| `VITE_REVERB_PORT` | منفذ WebSocket | `8080` |
| `VITE_REVERB_SCHEME` | `http` للتطوير أو `https` للإنتاج | `http` |
| `VITE_FIREBASE_API_KEY` | مفتاح تطبيق Firebase Web العام | من إعدادات تطبيق Firebase |
| `VITE_FIREBASE_AUTH_DOMAIN` | نطاق مصادقة مشروع Firebase | من إعدادات تطبيق Firebase |
| `VITE_FIREBASE_PROJECT_ID` | معرّف مشروع Firebase | من إعدادات تطبيق Firebase |
| `VITE_FIREBASE_MESSAGING_SENDER_ID` | معرّف مرسل FCM | من إعدادات تطبيق Firebase |
| `VITE_FIREBASE_APP_ID` | معرّف تطبيق Firebase Web | من إعدادات تطبيق Firebase |
| `VITE_FIREBASE_VAPID_KEY` | مفتاح Web Push العام | من إعدادات Web Push في Firebase |

في التطوير المحلي، اسمح بعنوان التطبيق في `FRONTEND_URL` بإعدادات Laravel/CORS. استخدم عنوان الإنتاج الفعلي عند النشر، أو اترك المتغير فارغًا لو الـAPI والواجهة على نفس الأصل.

## تسجيل الدخول

- الدخول بيقبل البريد الإلكتروني أو رقم الموبايل المسجل والفريد في ملف مريض مربوط بحساب المستخدم.
- كلمة المرور والتحقق من بيانات الدخول بيتموا في Laravel؛ التطبيق لا ينشئ حسابات ولا يغيّر أدوار المستخدمين.
- الحساب لازم يكون موجودًا ومربوطًا بسجل مريض. إنشاء الحسابات يظل عبر الإجراء الإداري الموثوق الموجود في النظام.
- رمز Sanctum محفوظ في `sessionStorage` للجلسة الحالية فقط، وبيتحذف عند تسجيل الخروج أو انتهاء الجلسة.
- مفيش OTP أو استعادة كلمة مرور عامة في الـAPI الحالي، لذلك التطبيق لا يعرض تدفقًا غير مدعوم.

## الشاشات والـAPI

| الشاشة | وظائفها | نقاط النهاية |
| --- | --- | --- |
| الدخول | بريد/موبايل وكلمة مرور، حفظ جلسة قصيرة | `POST /api/v1/login`, `GET /api/v1/me`, `DELETE /api/v1/logout` |
| الرئيسية | ملخص طلبات ونتائج وكتالوج فعلي | `GET /api/v1/patient/orders`, `GET /api/v1/patient/results`, `GET /api/v1/tests` |
| التحاليل | بحث بالاسم أو الكود وأسعار المختبر | `GET /api/v1/tests` |
| سحب منزلي | اختيار تحاليل وفرع نشط وعنوان وموعد مفضّل | `GET /api/v1/patient/branches`, `GET/POST/PUT/DELETE /api/v1/patient/addresses`, `POST /api/v1/patient/home-collections` |
| طلباتي | تتبع حالة الطلب والعينات وبيانات الزيارة | `GET /api/v1/patient/orders` |
| نتايجي | النتائج المعتمدة وتنزيل تقرير PDF مصرح به | `GET /api/v1/patient/results`, `GET /api/v1/results/{result}/document` |
| حسابي | بيانات المريض والعناوين المحفوظة | `GET /api/v1/patient/profile`, `GET/POST/PUT/DELETE /api/v1/patient/addresses` |

المسارات في الكود مستوردة من ملفات Wayfinder المولّدة داخل `src/actions` و`src/routes`. بعد تعديل مسارات Laravel، أعد التوليد من جذر المشروع:

```powershell
php artisan wayfinder:generate --with-form --path=patient-app/src --no-interaction
```

## طلب السحب المنزلي

السعر والخصم لا يُعتمدان على حساب الواجهة؛ Laravel يعيد التحقق من التحاليل النشطة ويحسب الإجمالي من السعر الحالي. الموعد الذي يختاره المريض هو **وقت مفضّل مطلوب** وليس تأكيد توافر. النظام الحالي لا يحتوي على جدول مواعيد أو سعة/توافر مُدار لكل فرع، لذلك المختبر هو من يؤكد الموعد ويتابع الطلب من لوحة العمل. يتم حفظ نسخة من العنوان على الطلب حتى لا يتغير سجل الزيارة إذا عُدّل العنوان المحفوظ لاحقًا.

الطلبات تظهر في واجهة الطلبات الحالية للموظفين مع عنوان الزيارة وموعدها. الحالات المعروضة مبنية على حالات الطلب والعينة الموجودة في النظام؛ لا توجد حاليًا حالات منفصلة مثل «المندوب في الطريق».

## الخصوصية والنتائج

- الـAPI يقصر سجل الطلبات والنتائج والعناوين على ملف المريض المرتبط بالمستخدم المصادق عليه.
- النتائج غير المعتمدة لا تظهر للمريض.
- التقرير يُحمّل من endpoint خاص بعد فحص ملكية المريض واعتماد النتيجة وكون الملف PDF، ولا توجد روابط عامة للملفات.
- الملف ينزل مؤقتًا للمتصفح ولا يُخزّن في تخزين التطبيق الدائم.

## Reverb وFirebase Push

التطبيق يستقبل تحديثات Reverb على قناة خاصة بسجل المريض عند إنشاء طلب (بما فيه السحب المنزلي) أو استلام عينة أو اعتماد نتيجة. القناة بتتحقق من هوية المريض المرتبط بالحساب، والرسالة اللحظية لا تتضمن قيم التحاليل. الشاشات بتعيد تحميل بياناتها بعد التحديث، ويظهر تنبيه مؤقت داخل التطبيق.

تحديثات Reverb لحظية أثناء استخدام التطبيق. إشعارات Firebase Push منفصلة عنها، وتظهر للمريض حتى لو التطبيق في الخلفية أو الشاشة مقفولة، بعد ما يفعّلها بنفسه من زر الإشعارات. التسجيل بيتم على endpoint المصادق عليه، وعند تسجيل الخروج بيتلغى تسجيل الجهاز. محتوى الإشعار يقتصر على تحديث عام ورقم الطلب، من غير قيم التحاليل أو التقرير.

لتفعيل Push:

1. فعّل Firebase Cloud Messaging في مشروع Firebase، واضبط إعداد Web Push واستخرج VAPID key.
2. انسخ القيم العامة في `patient-app/.env`، أو مرّرها لمتغيرات البيئة لخدمة `app` في Docker Compose.
3. ضع ملف Firebase Admin service account في المسار المحدد بـ`FIREBASE_CREDENTIALS` على الخادم، من غير إضافته للمستودع.
4. أعد تشغيل/بناء تطبيق المريض وعامل الطابور، واضبط HTTPS في بيئة النشر. إشعارات المتصفح تحتاج HTTPS، باستثناء `localhost` للتطوير.

على iPhone، دعم Web Push يتطلب iOS 16.4 أو أحدث وإضافة بوابة المريض للشاشة الرئيسية وفتحها كتطبيق ويب. أما تكامل Capacitor الأصلي مع FCM/APNs وإعدادات Android/iOS فما زال يحتاج خطوة منفصلة بعد اعتماد نسخة التطبيق.

## Capacitor

المشروع React مستقل، اتجاه RTL والمسارات والمكونات لا تعتمد على واجهات متصفح خاصة. بعد اعتماد نسخة الويب يمكن إضافة Capacitor، ثم استبدال تنزيل الملفات ومشاركة الروابط وبيانات الموقع بإضافات Capacitor المناسبة. إعدادات Firebase العامة تُحقن من متغيرات البيئة، ومفتاح Admin يظل على الخادم فقط.

## إمكانيات غير موجودة في الـAPI الحالي

لا توجد حاليًا جداول أو APIs لعروض الباقات الطبية أو كوبونات المريض أو رابط/مكافآت دعوة الأصدقاء. خصومات الإحالات الموجودة مخصصة لإحالات الأطباء وليست كوبونات مرضى؛ لذلك لم تُعرض في التطبيق كعروض وهمية. يلزم اعتماد قواعد العمل ولوحة إدارة لها قبل إضافتها.
